# Cline Rules (.clinerules)

## Core Operating Principles
- **Working Directory & Project Root:** The primary working directory for all game development and file operations is `C:\Dev\AI-GAMES\Kitty Vs Everything`.
- **Git Root & Remote:** The overarching Git repository root is `C:\Dev\AI-GAMES` (Remote: `https://github.com/digitelrezen/AI-Games.git`). Run git push/commit operations tracking back to this root or via standard working tree management.
- **No Screenshots:** Never capture or view screenshots/images under any circumstances. All operations, verification, and code inspections must be handled strictly through text, code parsing, and terminal commands.
- **Terminal Hygiene:** Always clear the terminal buffer (e.g., run `cls` on Windows or the equivalent clear command) before executing new command blocks to prevent reading stale log outputs.
- **Submodules/Working Tree:** Treat nested folders (including E6 nested directory structures) as a standard working tree; stage and commit locally within their respective directories.

## Game Development & Automation Workflow
- **Build Validation:** Always run the automated build/check script immediately when finished making any code or asset changes to ensure a clean build.
- **Version Tracking:** Always increment and sync version numbers using the wildcard schema (`v3.x.*.*`) in `package.json` and main config files with every major revision or milestone.
- **Build & Version Control Protocol:** Always execute the project build script following code modifications, review the outputs, and then systematically stage, commit, and push the changes.
- **Bundle Build Transformation (v3.83.0):** The build inlines source comments and normalizes code (single→double quotes, `game`→`game2` variable renaming). Therefore `tools/verify-bundle.mjs` checks must be written **quote-agnostic** (match `["']mob["']`, not a single-quoted literal) and must not rely on exact source spacing. **Symbol-absence checks** (e.g. "DROP_RARITY is gone") must target the actual gate — definition (`DROP_RARITY = {`) + property access (`.enemy` / `.special`) — rather than a whole-string `includes()`, because historical changelog comments that reference old symbol names are inlined into the bundle and would otherwise false-fail.

## ES Module Layout Conventions (v3.75.0)
- **Enemy Sprite Isolation (Phase 2):** `js/enemies/` holds AI/movement/health/combat behavior modules only. Standard enemy sprite/art pipelines live in `js/enemies/sprites/` (currently `Wasp2Sprite.js`).
- **Boss Boundary (Phase 1):** Boss art + behavior stay together in `js/bosses/` (`BlackCatSprite.js`, `PinkCatSprite.js`, `PinkCatBossArt.js`) — never move boss sprites into `js/enemies/sprites/`.
- **Enemy Parameter Standardization (Phase 2):** Enemy tunable stats (speed, hp, damage, fireRate) live only in `ENEMY_TYPES` in `js/core/config.js`; score lives in `TIERS`. Enemy modules must not hardcode or override these stats — they are assigned once in `EnemyBase`.
- **Off-Screen Escape Opt-Out (v3.82.0):** Enemies that intentionally fly off-screen (the shuttle's round-trip flyby) set `this.noEscape = true` in their constructor to opt out of the 80px off-screen cull in `EnemyBase.update()`. Every other enemy relies on that cull to end off-screen escapes — never remove or weaken it.

## Crisp Pixel Rendering Scope (v3.89.0, v3.90.0, v3.95.0)
- **Game + Hangar Canvases Only:** `image-rendering: pixelated` + `crisp-edges` are scoped in `style.css` strictly to the `#game-canvas` and `#hangar-canvas` rules. Never apply a global `canvas` / `.pixel-art` / `img` selector or any UI-element pixelation rule — the v3.88.0 global rule pixelated the hangar hero preview and UI (jagged + blurry selection screen) and was reverted in v3.88.1.
- **Crisp Hangar Preview (v3.89.0; native 256×384 in v3.90.0; in-game pipeline in v3.95.0; EXACT in-game scale in v3.98.0):** `#hangar-canvas` is the square 384×384 showcase stage (CSS = buffer at DPR 1) and `main.js` renders the IN-GAME sprite pipeline onto a ×DPR buffer — `PlayerShipArt.drawSpriteShip` (the exact path `PlayerRenderer` uses in-game: 70px frame × `MAIN_SHIP_SCALE` × `HANGAR_ZOOM` 1.0 + theme glow + `SHIP_GEOMETRY` hardpoint FX) — centered on the FIXED stage midpoint (192, 192), completely stationary (no bounce, no animation). v3.98.0: `HANGAR_ZOOM` dropped 2.0 → 1.0 so the selection screen shows the ship at its EXACT in-game size (no showcase zoom). The v3.89.0/v3.90.0 content-box path (`HANGAR_K` / `hangarMetrics` / `measureHangarSprite`) is gone (v3.95.0) — the selection screen now shows the ship exactly as it flies. The browser's buffer→CSS downsample is a uniform integer block, so `pixelated` reproduces the art crisply (no bilinear blur, no v3.88.0-style non-integer jaggedness). One pipeline, one center for all 9 ships; the procedural `PlayerRenderer` hull is the fallback until the sprite decodes. `ViewScaler.js` fit-to-window scales the WHOLE 1280×720 stage uniformly (logical stage is exactly 1280×720 at 16:9 and stretches height at other aspect ratios) — at integer stage scales the hangar is a perfect on-screen integer block; at non-integer stage scales it behaves exactly like `#game-canvas`.
- **Asset Import Policy (v3.90.0):** `tools/import-assets.mjs` normalizes normal shared transparent PNGs to ≤128px, but `cat_*` Catship art embeds at native size under the ≤512px catship ceiling — the native 256×384 frame is preserved end-to-end (asset → `AssetSprites.js` registry → in-game `drawSpriteShip` pipeline / hangar preview). Never re-introduce a global 512px cap or downscale `cat_*` art.
- **Context Smoothing:** `utils.disableImageSmoothing()` (standard + webkit/moz/ms fallbacks) is applied to the main gameplay canvas (`Game.js` init + re-applied by `ViewScaler.js` after EVERY buffer resize, since a `canvas.width` assignment resets 2D context state), the hangar hero canvas (`main.js`, after its DPR buffer sizing), and the offscreen sprite buffers (`AssetManager.js` cache, `PowerUp.js` jewel buffer). All other UI canvases keep default bilinear smoothing; the intentional one-shot asset-downscale passes (`Wasp2Sprite.js`, `AsteroidSprite.js`) keep their explicit `imageSmoothingEnabled = true` opt-in on their own offscreen contexts.
- **Check Pin:** `tools/check/sections/06ag-crisp-rendering.mjs` enforces the scope (CSS `#game-canvas` + `#hangar-canvas` block regexes, global-selector absence, `disableImageSmoothing` in Game/ViewScaler/AssetManager/PowerUp/main, the `drawSpriteShip` in-game-pipeline blit on the 384×384 stage centered on (192, 192), and the bilinear opt-ins) — keep it in sync with any rendering-path change.
