───────────────────────────────────────────────────────────────────
  1. ENTRY & APP SHELL  (4 files)
───────────────────────────────────────────────────────────────────
  index.html      App shell: canvas, main menu (5 .ship-option cards),
                  game-over + leaderboard lists, touch UI, HUD DOM;
                  loads main.js as the ES-module entry point.
  style.css       All styling: layout, menu cards, HUD bars, touch-
                  button colors, and the .hidden utility class.
  main.js         Entry point: boots Game, wires #start-btn/#retry-btn/
                  #save-score, .ship-option theme selection, Enter
                  shortcut; also carries the project manifest comment.
  Game.js         Orchestrator: state machine, fixed update loop, all
                  collision detection, scoring, starfield, render
                  dispatch. v3.13.0: W/H mirror the live viewW/H and
                  re-sync on resize (ultra-wide tracking).

───────────────────────────────────────────────────────────────────
  2. CORE INFRASTRUCTURE  (6 files)
───────────────────────────────────────────────────────────────────
  config.js       Single source of truth for tunables: GAME dims
                  (native 1280x720 REFERENCE since v3.13.0),
                  WEAPONS, PLAYER_THEMES, ENEMY_TYPES/TIERS, BONUS.
  Viewport.js     v3.13.0 viewport fit math: computeViewport() ->
                  viewW/H (constrained axis native, other stretches,
                  zero letterboxing), buffer scale q (<= 3),
                  ULTRA_WIDE_PRESETS (3440x1440 / 5120x1440 native).
  ViewScaler.js   Applies computeViewport: CSS scale() on #game-root,
                  canvas buffer viewW*q x viewH*q, identity ctx
                  transform (Game.js ctx.scale(q) per frame).
  utils.js        Shared math helpers: TAU, rand, clamp, dist2,
                  angleTo, pick.
  EventBus.js     Global pub/sub `bus` for UI events (banner, score,
                  life) so game logic never touches the DOM directly.
  Entity.js       Base class for every actor: position, velocity,
                  radius, hp/shield, alive flag.

───────────────────────────────────────────────────────────────────
  3. PLAYER SHIPS / ART  (9 files)

  KEY CROSS-FILE CONTRACTS (refactor hot spots)
═══════════════════════════════════════════════════════════════════
  • DOM ids      : main.js, Game.js, HUD.js, InputManager.js all
                   reference ids that must match index.html —
                   #game-canvas, #start-btn, #retry-btn, #save-
                   score, #initials, #menu-scores-list, #go-scores-
                   list, #version-label, #touch-ui, #joy-base/
                   #joy-knob, #btn-fire/#btn-boost/...
  • Theme IDs    : index.html data-theme ↔ CatShipFactory REGISTRY ↔
                   PLAYER_THEMES keys in config.js (yellow/orange/
                   white/gray/brown).
  • Enemy types  : EnemyFactory REGISTRY keys ↔ ENEMY_TYPES in
                   config.js ↔ WaveManager wave definitions ↔
                   DevPanel spawn list.
  • Viewport     : v3.13.0 — GAME.W/H is the native 1280x720
                   REFERENCE only; live bounds = game.viewW/H (Game
                   W/H mirror them, re-sync on resize). Spawn/bounds/
                   centering code uses live bounds.
  • Weapon IDs   : WEAPONS keys in config.js ↔ Player/MiniShip fire
                   code ↔ Combat.applyWeaponHit rules ↔ DevPanel.
  • Ultimates    : Game.js createCatShip call is the single player
                   spawn path; ULTIMATE_COOLDOWN/ultimateName are
                   set per variant class.
  • EventBus     : `bus` event names (e.g. 'banner') are the game-
                   logic → HUD bridge; keep names stable.
