HazardBase.js         Base class for all 10 hazard types (HAZARD_TYPES in
                      js/core/config/hazards.js): non-lootable, shootable
                      environmental obstacles. Continuous drift along a FIXED
                      heading (no steering/AI) until (a) shot down by the
                      player (Collisions.js friendly-bullet loop ->
                      HazardManager.explode, byPlayer -> score, ZERO loot),
                      (b) proximity-fuse trigger (Prox Mine) or direct
                      contact with the player fleet -> _detonate (byPlayer
                      false: blast + AoE damage, no score), or (c) drifts
                      fully off-screen -> silent despawn (no explosion, no
                      score). applyDamage() honors the v3.83.0 off-screen
                      kill gate (utils.isOnScreen) exactly like EnemyBase -
                      hazards only take damage while visible. Rendering: the
                      256x256 hazard PNG (key "hazard_<type>", embedded
                      128x128 via tools/import-assets.mjs) through the
                      AssetManager pipeline, procedural drum/bomb glyph
                      fallback, durability arc once hit, proximity warning
                      ring.
HazardFactory.js      createHazard() + pickSpawnVector(): the "enter from ANY
                      direction" rule - random edge (top/right/bottom/left),
                      a random point fully off-screen past HAZARD.EDGE_MARGIN,
                      and a random interior target so the heading always
                      crosses the playfield (straight or diagonal).
HazardManager.js      THE independent spawner + per-frame driver (game.hazards):
                      owns its own list/rings/pools/flash state and spawn
                      timer (HAZARD.SPAWN_MIN..MAX, capped at
                      HAZARD.MAX_CONCURRENT), active during combat waves only
                      (bonus rounds stay hazard-free). explode(game, hz,
                      {byPlayer}) detonates per HAZARD_TYPES[type].explosion:
                      bio (green splatter + toxic pool), fire (orange burst +

net/ - MULTIPLAYER / LAN / E6 (11 modules + net/data/ 3 E6 files)
=====================================================================
Host-authoritative LAN co-op: the HOST browser simulates the full game (P1 + P2) and
broadcasts authoritative state; the CLIENT browser sends P2 input and mirrors the
host's world (no local physics). P2 is a full second CatShipFactory ship (not a
visual clone) with its own HP/shield/lives/score, auto-aim, and per-player scoring.
E6.js                 The project's standard plain-text record codec (pure, no DOM).
                      Line-oriented, pipe-delimited, "#E6 <schema> v<major>.<minor>"
                      header + "#FIELDS f1|f2|..." schema mapping + record rows.
                      Values escaped (\\ -> \\\\, | -> \\|, newline -> \\n);
                      splitRow only guards against splitting on an escaped pipe and
                      preserves backslashes so unescapeValue (single-pass) can
                      process them. Used for ALL config, profiles, and wire-state.
NetProtocol.js        Wire protocol. JSON envelope (hello/welcome/input/state/event/
                      bye); the state collections (players/enemies/boss) are
                      serialized as E6 record rows. Fixed field order: player:
                      id|theme|x|y|angle|hp|shield|weapon|minis|score|lives|alive,
                      enemy: id|type|x|y|hp|angle, boss: active|hp|maxHp|phase|x|y.
NetSettings.js        Multiplayer config (E6 schema "netsettings":
                      role|hosting|port|hostIp|syncRate), persisted to localStorage +
                      export/import as multiplayer.config.e6. Roles:
                      solo|coop|host|client.
PlayerProfile.js      Per-player profiles (E6 schema "profile": slot|theme|callsign|
                      score), persisted to localStorage + export/import as
                      player1.profile.e6 / player2.profile.e6.
Player2Controls.js    P2 keyboard input: a SEPARATE keybind set + input state
                      (action-layer compatible: isDownAction/wasPressedAction).
NetClient.js          Browser WebSocket client (host + client roles); connect(),
                      sendInput(), onState/onEvent/onWelcome/onClose callbacks,
                      status for the net HUD.
NetSync.js            Host-side sync: broadcasts encodeState(game, seq) at syncRate
                      Hz, applies the remote P2's input stream to coopManager.
CoopManager.js        Spawns P2 via createCatShip, sets game.players=[p1,p2] +
                      game.player2, applies PLAYER2 HP/shield/lives scaling, drives
                      P2 from local keyboard (local) or remote input (remote), P2
                      auto-aim, co-op game-over (both ships dead).
ClientMirror.js       Client-side mirror: sends P2 input, maintains mirror
                      Player/Enemy/Boss instances from host state, renders the mirror
                      world, and updates the local game.player/game.player2
                      placeholders for the HUD.
NetSettingsUI.js      The #net-settings panel in the settings screen: role select,
                      host IP/port, HOST GAME / JOIN GAME buttons, net status, E6
                      export/import.
server.mjs            Node ws relay (Node-only, NOT inlined into the build). Pure
                      relay enforcing host-authoritative direction: host->client
                      state/event/welcome, client->host input/hello, either->other
                      bye. Run with npm run lan.
data/multiplayer.config.e6, data/player1.profile.e6, data/player2.profile.e6
                      E6 data files. A lan-state.e6 is NOT required - live state is
                      sent over the wire in real-time (E6 blocks inside a JSON state
                      message), never persisted to disk; the relay server holds no
                      state.

- Stage flow (v3.76.0): LevelRegistry.STAGE_SEQUENCE is the single source of truth
  for stage cadence; Game.js drives activeStage.update(dt) / isComplete(); new
  bonus stages register in BONUS_STAGES and implement the uniform interface

  DevPanel forced bonuses go through levelRegistry.forceBonus().

  over js/core/config/ (viewport/player/weapons/enemies/drops/stages) - the public
  surface (24 named exports) is unchanged; new tunables go into the matching
  submodule and are re-exported from config.js.
- Game.js thin shell (v3.77.0 E6): Game.js delegates to js/core/game/ (StageFlow/
  DisplayPolicy/GameOver/Gameplay); submodules take `game` as first parameter and
  Game.js calls them with `this`. Source-level gate pins stay in Game.js (gates
  read the file directly): VERSION ([6aa]), LevelRegistry import + activeStage
  core-loop lines ([6z]), stunRockets/napalmRockets imports + update(this, dt)
  ticks ([6w]), "type: rollPowerUpDrop()" + collectPowerUp prototype ([2]),
  shuttle wave event currentSpecies === 'shuttle' / SHUTTLE INTERCEPT ([6ab]),
  this.bonus.draw(ctx) hook ([6h]).
- Build entry + tooling: esbuild bundles js/core/main.js + the whole import graph
  (new submodules are picked up automatically); tooling lives in the shared
  C:\Dev\AI-GAMES\tools (check.mjs gate sections under check/sections/, validate.mjs,
  smoke.mjs, harness.mjs, import-assets.mjs, derive-cat-sprites.mjs).
- DOM ids: main.js, Game.js, HUD.js, InputManager.js reference ids that must match
  index.html: #game-canvas, #start-btn, #retry-btn, #save-score, #initials,
  #menu-scores-list, #go-scores-list, #version-label, #touch-ui, #joy-base/
  #joy-knob, #btn-fire/#btn-boost/...
- Theme IDs: the generated data-theme cards <-> CatShipFactory REGISTRY <->
  PLAYER_THEMES keys in config.js (9 themes: yellow/orange/white/gray/brown/blue/
  red/green/black; 5 have dedicated variant classes in js/player/variants/).
- Enemy types: EnemyFactory REGISTRY keys <-> ENEMY_TYPES in config.js <->
  WaveManager wave definitions <-> DevPanel spawn list.
- Viewport: GAME.W/H in config.js is the native 1280x720 REFERENCE only. Live bounds
  are game.viewW/viewH (Game W/H mirror them and re-sync on resize) - all

- Weapon IDs: WEAPONS keys in config.js <-> Player/MiniShip fire code <->
  Combat.applyWeaponHit rules <-> DevPanel.
- Ultimates: the createCatShip call in Game.js is the single player spawn path;
  ULTIMATE_COOLDOWN/ultimateName are set per variant class.
- EventBus: the bus event names (e.g. "banner") are the game-logic -> HUD bridge;
  keep names stable.
- Internet entourage: InternetBonus tags the 8 orbiting Black Cats with entourage =
  true + entouragePhase; BlackCatEnemy.draw() renders the outfit via
  BlackCatEntourage.drawEntourageOutfit(); pendant time comes from
  RealTimeClock.realTimeClock (started/stopped by InternetBonus, ticked in its
  update). Art never touches Date; the clock module never draws.

  for docked vs deployed. false = minis docked + INERT (no fire, no weapon anim);

  MiniShip.update skips dock-snapping when deployed. Weapon animation state
  (vulkanSpin / railCharge / plasmaPulse) is owned by WeaponAnim.js, ticked by
  Player/MiniShip, surfaced by PlayerShipArt/PlayerMiniArt, rendered by
  PlayerShipFx.drawWeaponPaw.

  config.js, main.js, Game.js, HUD.js and index.html carry the same milestone
  version; check.mjs [6aa] keeps them in lockstep.
